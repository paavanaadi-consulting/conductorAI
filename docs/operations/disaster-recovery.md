## 2. Redis Backup and Restore

Redis serves as the backbone for both the MessageBus (pub/sub) and StateManager (state persistence). Data loss in Redis means loss of all in-flight workflow state.

### 2.1 RDB Snapshots (Point-in-Time Backups)

RDB creates binary snapshots of the entire Redis dataset at configurable intervals.

```ini
# redis.conf -- RDB snapshot configuration
# Snapshot every 60 seconds if at least 100 keys changed
save 60 100

# Snapshot every 300 seconds if at least 10 keys changed
save 300 10

# Snapshot every 900 seconds if at least 1 key changed
save 900 1

# RDB file location
dbfilename conductor-dump.rdb
dir /data/redis/

# Compression (reduces backup size ~60%)
rdbcompression yes
rdbchecksum yes

# Stop writes on RDB save failure (data safety)
stop-writes-on-bgsave-error yes
```

**Backup Script:**

```bash
#!/bin/bash
# redis-backup.sh -- Automated RDB backup to S3
set -euo pipefail

REDIS_HOST="${REDIS_HOST:-redis.internal}"
REDIS_PORT="${REDIS_PORT:-6380}"
REDIS_PASSWORD="${REDIS_PASSWORD}"
S3_BUCKET="${S3_BUCKET:-conductorai-backups}"
TIMESTAMP=$(date +%Y%m%d-%H%M%S)
BACKUP_DIR="/tmp/redis-backup"

mkdir -p "${BACKUP_DIR}"

# Trigger a background save
redis-cli --tls -h "${REDIS_HOST}" -p "${REDIS_PORT}" -a "${REDIS_PASSWORD}" BGSAVE

# Wait for save to complete
while [ "$(redis-cli --tls -h "${REDIS_HOST}" -p "${REDIS_PORT}" -a "${REDIS_PASSWORD}" LASTSAVE)" == "$(cat /tmp/last_save 2>/dev/null || echo 0)" ]; do
    sleep 1
done
redis-cli --tls -h "${REDIS_HOST}" -p "${REDIS_PORT}" -a "${REDIS_PASSWORD}" LASTSAVE > /tmp/last_save

# Copy the RDB file
cp /data/redis/conductor-dump.rdb "${BACKUP_DIR}/conductor-dump-${TIMESTAMP}.rdb"

# Upload to S3 with server-side encryption
aws s3 cp "${BACKUP_DIR}/conductor-dump-${TIMESTAMP}.rdb" \
    "s3://${S3_BUCKET}/redis/rdb/${TIMESTAMP}/conductor-dump.rdb" \
    --sse aws:kms

# Retain last 30 days of backups
aws s3 ls "s3://${S3_BUCKET}/redis/rdb/" | while read -r line; do
    backup_date=$(echo "$line" | awk '{print $1}')
    if [[ $(date -d "${backup_date}" +%s 2>/dev/null || date -j -f "%Y-%m-%d" "${backup_date}" +%s) -lt $(date -d "30 days ago" +%s 2>/dev/null || date -v-30d +%s) ]]; then
        folder=$(echo "$line" | awk '{print $NF}')
        aws s3 rm "s3://${S3_BUCKET}/redis/rdb/${folder}" --recursive
    fi
done

echo "[$(date)] RDB backup completed: conductor-dump-${TIMESTAMP}.rdb"
```

### 2.2 AOF (Append-Only File) for Durability

AOF logs every write command, providing near-zero data loss at the cost of disk I/O.

```ini
# redis.conf -- AOF configuration
appendonly yes
appendfilename "conductor-appendonly.aof"
appenddirname "appendonlydir"

# fsync policy:
# - always: fsync every write (safest, slowest -- RPO: 0)
# - everysec: fsync every second (good balance -- RPO: ~1 second)
# - no: let OS decide (fastest, least safe)
appendfsync everysec

# Auto-rewrite AOF when it grows 100% beyond last rewrite
auto-aof-rewrite-percentage 100
auto-aof-rewrite-min-size 64mb

# Don't fsync during rewrite (better performance)
no-appendfsync-on-rewrite no
```

### 2.3 Restore Procedures

#### Restore from RDB Snapshot

```bash
#!/bin/bash
# redis-restore-rdb.sh -- Restore Redis from RDB snapshot
set -euo pipefail

S3_BUCKET="${S3_BUCKET:-conductorai-backups}"
RESTORE_TIMESTAMP="${1:?Usage: redis-restore-rdb.sh <timestamp>}"

echo "[$(date)] Starting Redis RDB restore from ${RESTORE_TIMESTAMP}"

# 1. Stop Redis
sudo systemctl stop redis

# 2. Download the RDB file
aws s3 cp \
    "s3://${S3_BUCKET}/redis/rdb/${RESTORE_TIMESTAMP}/conductor-dump.rdb" \
    /data/redis/conductor-dump.rdb \
    --sse aws:kms

# 3. Verify checksum
redis-check-rdb /data/redis/conductor-dump.rdb
if [ $? -ne 0 ]; then
    echo "ERROR: RDB checksum verification failed"
    exit 1
fi

# 4. Start Redis (loads RDB on startup)
sudo systemctl start redis

# 5. Verify data
redis-cli --tls -h localhost -p 6380 -a "${REDIS_PASSWORD}" DBSIZE
redis-cli --tls -h localhost -p 6380 -a "${REDIS_PASSWORD}" \
    KEYS "conductor:workflow:*" | head -5

echo "[$(date)] RDB restore completed"
```

#### Restore from AOF

```bash
#!/bin/bash
# redis-restore-aof.sh -- Restore Redis from AOF
set -euo pipefail

echo "[$(date)] Starting Redis AOF restore"

# 1. Stop Redis
sudo systemctl stop redis

# 2. Verify and fix AOF file
redis-check-aof --fix /data/redis/appendonlydir/conductor-appendonly.aof.*.aof

# 3. Start Redis (replays AOF on startup)
sudo systemctl start redis

# 4. Verify
redis-cli --tls -h localhost -p 6380 -a "${REDIS_PASSWORD}" INFO persistence

echo "[$(date)] AOF restore completed"
```

## 3. Workflow State Reconstruction

When Redis data is lost or corrupted, workflow state can be partially reconstructed from available sources.

### 3.1 Reconstruction from StateManager

```python
"""Workflow state reconstruction after Redis restore."""
import asyncio
from conductor.orchestration.state_manager import InMemoryStateManager
from conductor.core.state import WorkflowState, AgentState
from conductor.core.enums import TaskStatus, WorkflowPhase

async def verify_state_integrity(state_manager):
    """Verify workflow state consistency after restore.

    Checks:
    1. All referenced task results exist
    2. Phase history is consistent with current phase
    3. No orphaned agent states
    """
    # Get all workflow states
    # Note: In production, you would iterate over known workflow IDs
    # or scan Redis keys matching the pattern
    workflow_ids = []  # Populated from Redis SCAN "conductor:workflow:*"

    issues = []

    for wf_id in workflow_ids:
        wf_state = await state_manager.get_workflow_state(wf_id)
        if wf_state is None:
            issues.append(f"Missing workflow state: {wf_id}")
            continue

        # Check task results exist
        for task_id, result in wf_state.task_results.items():
            stored_result = await state_manager.get_task_result(task_id)
            if stored_result is None:
                issues.append(f"Missing task result: {task_id} (workflow: {wf_id})")

        # Check phase history consistency
        if wf_state.status == TaskStatus.IN_PROGRESS:
            if not wf_state.phase_history:
                issues.append(f"In-progress workflow with no phase history: {wf_id}")

    return issues


async def reconstruct_workflow_from_artifacts(
    state_manager,
    artifact_store,
    workflow_id: str,
) -> WorkflowState:
    """Attempt to reconstruct a workflow state from artifact store.

    If Redis state was lost but artifacts were preserved (e.g., in S3),
    we can rebuild the WorkflowState from the artifact records.

    Args:
        state_manager: Active StateManager.
        artifact_store: Active ArtifactStore with preserved artifacts.
        workflow_id: The workflow to reconstruct.

    Returns:
        Reconstructed WorkflowState (may be incomplete).
    """
    artifacts = await artifact_store.list_by_workflow(workflow_id)

    # Reconstruct task results from artifacts
    task_results = {}
    for artifact in artifacts:
        if artifact.artifact_type == "task_result":
            # Parse the stored TaskResult from artifact content
            import json
            from conductor.core.models import TaskResult
            result = TaskResult.model_validate_json(artifact.content)
            task_results[result.task_id] = result

    # Create a reconstructed workflow state
    state = WorkflowState(
        workflow_id=workflow_id,
        current_phase=WorkflowPhase.DEVELOPMENT,  # Unknown; needs manual review
        status=TaskStatus.FAILED,  # Mark as failed until verified
        task_results=task_results,
    )

    await state_manager.save_workflow_state(state)
    return state
```

### 3.2 Reconstruction Decision Matrix

| Data Available | Action | Expected Recovery |
|---------------|--------|------------------|
| RDB snapshot < 5 min old | Restore from RDB | Full recovery within RPO |
| AOF file intact | Restore from AOF | Near-complete recovery (< 1 sec data loss) |
| Both RDB and AOF | Restore from AOF (more recent) | Best recovery |
| Neither; artifacts in S3 | Reconstruct from artifacts | Partial recovery; manual review needed |
| Nothing available | Re-run affected workflows | Full re-execution required |

## 4. Multi-Region Failover

### 4.1 Redis Sentinel (High Availability)

Redis Sentinel provides automatic failover for Redis master/replica setups. ConductorAI supports Sentinel natively via `RedisConfig`.

```python
# ConductorConfig for Redis Sentinel deployment
from conductor.core.config import RedisConfig, ConductorConfig

config = ConductorConfig(
    environment="prod",
    redis=RedisConfig(
        sentinel_mode=True,
        sentinel_master="conductorai-master",
        sentinel_nodes=[
            "sentinel-0.region-a.internal:26379",
            "sentinel-1.region-a.internal:26379",
            "sentinel-2.region-b.internal:26379",
        ],
        ssl=True,
        password="${REDIS_PASSWORD}",
        max_connections=20,
        socket_timeout=5.0,
    ),
)
```

**Sentinel Architecture:**

```
Region A (Primary)                    Region B (DR)
┌─────────────────┐                  ┌─────────────────┐
│  Redis Master    │ ──replication──► │  Redis Replica   │
│  (read/write)    │                  │  (read-only)     │
└────────┬────────┘                  └────────┬────────┘
         │                                     │
┌────────▼────────┐                  ┌────────▼────────┐
│  Sentinel Node 1 │                  │  Sentinel Node 3 │
│  Sentinel Node 2 │                  │                   │
└─────────────────┘                  └─────────────────┘
         │                                     │
┌────────▼────────┐                  ┌────────▼────────┐
│  ConductorAI     │                  │  ConductorAI     │
│  Instance 1, 2   │                  │  Instance 3 (DR) │
└─────────────────┘                  └─────────────────┘
```

**Failover Triggers:**

| Trigger | Detection | Sentinel Action | RTO |
|---------|-----------|----------------|-----|
| Redis master crash | Sentinel `+sdown` event | Promote replica to master | < 30 seconds |
| Network partition | Sentinel quorum vote | Promote replica in reachable partition | < 30 seconds |
| Region A outage | All Region A Sentinels down | Region B Sentinel promotes local replica | < 60 seconds |

### 4.3 Application-Level Failover

```python
"""Application-level failover for ConductorAI."""
import asyncio
import structlog
from conductor.facade import ConductorAI
from conductor.core.config import ConductorConfig, RedisConfig
from conductor.infrastructure.health import HealthChecker, ComponentHealth

logger = structlog.get_logger()

class FailoverManager:
    """Manages automatic failover between primary and DR configurations."""

    def __init__(
        self,
        primary_config: ConductorConfig,
        dr_config: ConductorConfig,
        health_check_interval: int = 10,
        failover_threshold: int = 3,
    ):
        self.primary_config = primary_config
        self.dr_config = dr_config
        self.health_check_interval = health_check_interval
        self.failover_threshold = failover_threshold
        self._consecutive_failures = 0
        self._active_config = primary_config
        self._conductor: ConductorAI | None = None

    async def start(self) -> ConductorAI:
        """Start ConductorAI with primary config and begin health monitoring."""
        self._conductor = ConductorAI(self._active_config)
        await self._conductor.initialize()
        # Start background health monitor
        asyncio.create_task(self._health_monitor_loop())
        return self._conductor

    async def _health_monitor_loop(self):
        """Continuously monitor health and trigger failover if needed."""
        while True:
            await asyncio.sleep(self.health_check_interval)
            try:
                checker = HealthChecker(
                    state_manager=self._conductor.state_manager,
                    message_bus=self._conductor.message_bus,
                )
                status = await checker.check_all()

                if status.status == ComponentHealth.UNHEALTHY:
                    self._consecutive_failures += 1
                    logger.warning(
                        "health_check_failed",
                        failures=self._consecutive_failures,
                        threshold=self.failover_threshold,
                    )
                    if self._consecutive_failures >= self.failover_threshold:
                        await self._failover()
                else:
                    self._consecutive_failures = 0

            except Exception as e:
                self._consecutive_failures += 1
                logger.error("health_check_error", error=str(e))

    async def _failover(self):
        """Switch from primary to DR configuration."""
        logger.critical("failover_initiated")

        # Shutdown current instance
        try:
            await self._conductor.shutdown()
        except Exception:
            pass  # Best-effort shutdown

        # Switch to DR config
        self._active_config = self.dr_config
        self._conductor = ConductorAI(self._active_config)
        await self._conductor.initialize()
        self._consecutive_failures = 0

        logger.info("failover_completed", config="dr")
```

## 5. Communication Plan and Escalation

### 5.1 Severity Levels

| Level | Description | Examples | Response Time |
|-------|-------------|---------|---------------|
| **SEV1** | Complete system outage, no workflows can execute | Redis down, all LLM providers unreachable | Immediate (< 5 min) |
| **SEV2** | Major degradation, some workflows failing | Single LLM provider down, high error rates | < 15 min |
| **SEV3** | Minor degradation, performance impact | Elevated latency, non-critical component failure | < 1 hour |
| **SEV4** | Informational, potential issue detected | Disk space warning, certificate expiry approaching | < 24 hours |

### 5.2 Escalation Matrix

```

├── Automated alert fires (Prometheus → PagerDuty/OpsGenie)
├── On-call engineer acknowledged

│
Time = 15 min: Incident Response
├── SEV1: War room opened
│   ├── Engineering Lead
│   ├── SRE On-call

│   └── Communications lead

│

├── SEV1 unresolved → VP Engineering + CTO
```
