End-to-End Workflow Execution — Step by Step

1
User Submits Project (Next.js Frontend)
User fills in project name, uploads requirements.yaml + infrastructure.yaml, selects components (Code, Tests, Deployment...), and clicks Create & Run.
2
FastAPI Backend Receives Request
POST /api/projects/{id}/run → Projects router saves to SQLite, calls ConductorService. WebSocket connection opened for real-time progress.
3
Pipeline YAML Generation
PipelineYamlGeneratorAgent analyzes requirements + infra, detects pipeline type (data_pipeline, ml_pipeline, rag_llm, etc.), generates complete pipeline YAML via LLM.
4
WorkflowBuilder Maps Components to Agents
WorkflowBuilder maps UI checkboxes to agent types: code→CODING, unit_test→TEST, deployment→DEVOPS+DEPLOYING, etc. Builds ordered WorkflowDefinition with phases.
5
ConductorAI Facade → WorkflowEngine
conductor.run_workflow(definition) → Creates WorkflowState (PENDING → IN_PROGRESS), starts phase-by-phase execution.
6
DEVELOPMENT Phase
CodingAgent → generates source code via LLM
ReviewAgent → reviews code quality (score 1-10, approved/rejected)
TestDataAgent → generates test fixtures
TestAgent → generates unit tests
Each task: coordinator.dispatch_task() → find IDLE agent → agent.execute_task() → save TaskResult
7
Phase Gate Check
PolicyEngine.check() evaluates phase gate policies (success rate, agent availability). If passes → advance to next phase. If fails → workflow fails.
8
DEVOPS Phase
DevOpsAgent → generates CI/CD config (GitHub Actions YAML)
DeployingAgent → handles deployment to target environment
9
MONITORING Phase
MonitorAgent analyzes deployment result. If has_issues: true → triggers feedback loop back to DEVELOPMENT phase (up to 3x). Otherwise → workflow completes.
10
Results Returned to UI
WorkflowState (COMPLETED) returned through all layers. Frontend displays generated code, test results, CI/CD configs, deployment status, and review scores. User can download artifacts, view .context/ docs, or trigger PR creation.
